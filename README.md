# Дневник тренировок 🏋️

Простое приложение для записи тренировок в зале. Работает как **PWA** —
устанавливается на iPhone на домашний экран, открывается в полный экран и
**работает офлайн**. Все данные хранятся локально на устройстве (IndexedDB),
без бэкенда и без регистрации.

## Возможности

- **Лог тренировок** — дата, упражнения и подходы (повторения × вес),
  с добавлением, редактированием и удалением.
- **История** прошлых тренировок.
- **Графики прогресса** по каждому упражнению: максимальный вес,
  расчётный 1ПМ (формула Эпли) и суммарный объём, плюс рекорд/последнее/изменение.
- Полностью офлайн, тёмная тема, поддержка «чёлки» и индикатора iPhone (safe-area).

## Запуск (разработка)

```bash
npm install
npm run icons     # сгенерировать PNG-иконки из scripts/icon.svg (нужно один раз)
npm run dev       # http://localhost:5173
```

> Service worker в dev-режиме ограничен. Для проверки реального
> офлайна и установки используйте прод-сборку (ниже).

## Сборка и проверка PWA

```bash
npm run build     # прод-бандл в dist/ (service worker + manifest)
npm run preview   # http://localhost:4173 — как оно работает на устройстве
```

## Публикация на GitHub Pages (для запуска на телефоне)

Чтобы установить приложение на iPhone с офлайном, ему нужен доступ по HTTPS.
В репозитории уже есть workflow `.github/workflows/deploy.yml`, который при
пуше в `main` собирает приложение и публикует его на GitHub Pages.

Однократная настройка:

1. Репозиторий → **Settings** → **Pages**.
2. **Build and deployment** → **Source**: выберите **GitHub Actions**.
3. Дальше при каждом пуше в `main` (или вручную во вкладке **Actions** →
   *Deploy PWA to GitHub Pages* → **Run workflow**) сайт обновляется по адресу:

   **https://soa4work.github.io/training-app/**

> Приложение собирается с базовым путём `/training-app/` (под-путь Pages).
> Для корневого хостинга (Netlify/Vercel/свой домен) соберите с `BASE=/`:
> `BASE=/ npm run build`.

## Установка на iPhone

iOS не показывает автоприглашение установки. Ставится вручную:

1. Откройте адрес приложения (например, ссылку GitHub Pages выше) в **Safari**.
2. Нажмите **«Поделиться»** → **«На экран „Домой“»**.
3. Запустите с домашнего экрана — приложение откроется в полный экран и
   будет работать без интернета.

### Быстрая проверка по Wi-Fi (без установки)

```bash
npm run build && npm run preview -- --host
```
Откройте показанный адрес `Network: http://192.168.x.x:4173/training-app/` в
Safari на телефоне (в той же Wi-Fi-сети). Работает как обычный сайт; офлайн и
установка на домашний экран доступны только по HTTPS (см. GitHub Pages выше).

## Тесты

```bash
npm run build && npm run test   # Playwright smoke-тест против preview-сервера
```

Тест проверяет: русский интерфейс, создание тренировок, сохранение в IndexedDB
после перезагрузки, отрисовку графика прогресса и регистрацию service worker.

> Тесты и генерация иконок используют предустановленный Chromium по пути
> `/opt/pw-browsers/chromium`. На другой машине задайте свой путь:
> `CHROMIUM_PATH=/path/to/chrome npm run test`, либо установите браузеры
> Playwright командой `npx playwright install chromium` и уберите
> `executablePath` в скриптах.

## Архитектура

Код разделён на два слоя, чтобы приложение было **переносимым**:

```
src/
├── core/     # переносимое ядро — БЕЗ DOM: модель, хранилище (IndexedDB), аналитика
├── ui/       # интерфейс — рендер DOM, hash-роутер, экраны, SVG-график
└── i18n/     # все строки интерфейса (русский)
```

Правило: `core/` никогда не импортирует из `ui/`. Это упрощает будущий
**порт на iOS**:

- **Capacitor** — обернуть тот же `dist/` в нативную оболочку для App Store
  почти без изменений кода (меняется в основном `core/storage.js`, если нужно
  другое хранилище).
- **SwiftUI** — переписать только UI, переиспользовав модель данных и формулы
  аналитики из `core/` как спецификацию.

## Технологии

Vite + `vite-plugin-pwa` (Workbox), чистый JavaScript без фреймворка,
самописный SVG-график. Никаких CDN — всё бандлится локально ради офлайна.
